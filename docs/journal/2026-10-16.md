## TASK-036 - live `gt4-gs.exe` MVP (slice193)

The owner approved the TASK-034 images and the go-ahead for TASK-036. Branches: `task/036-gs-live` (from main
`57d1fa5`, after TASK-033/034/035 were merged in PR #26) and `gt4gs/live` in the fork (from `gt4gs/main`, PCSX2
v2.8.2). Report: [GS-LIVE](../GS-LIVE.md).

Fork (GPL, PCSX2-tainted work, nothing near CoreGS 2.0):

- Dependencies for v2.8.2 were built fresh (`private/slice193-gt4gs-deps`): the nightly set of TASK-034 had other
  versions (FFmpeg 9.0.1, SDL 3.4.18, plutovg 1.3.3). Friction: the fork's script finds Visual Studio only with
  `vswhere -products *` on a Build Tools install (fixed in the script), and `cmd` mis-jumps `call :label` in an
  LF-only batch file (the local copy was converted to CRLF). FFmpeg is not needed to build or run the GS (bundled
  headers, loaded at run time): built with `BUILD_FFMPEG=0`, about 15 minutes.
- `pcsx2/GSStreamReplayer` executes the protocol records; `pcsx2-gt4gs` builds `gt4-gs.exe`; the MIT protocol files
  are vendored by SHA-256 (LF form, `eol=lf`, so the check holds on any checkout). PCSX2 builds without C++
  exceptions; the transport is in its own library with exceptions behind a no-throw adapter.
- Console output: PCSX2 writes its console with `WriteConsoleW`, which fails on a pipe; a fallback writes UTF-8 text,
  so `gt4-gs.exe` lines appear in the game's session log.
- Commits `0b51d4c3c` and `acf4f986e`; tag `gt4gs-v0.2.0-live` (prerelease from CI).

Main (MIT):

- `gs_stream_client`: `GT4_GS_PROCESS_SHA256` pin check (Windows CNG), `GT4_GS_CONFIG` -> `--config`,
  `WS_CLIPCHILDREN` on the game window at attach, message box when the GS process dies with a window attached.
  CTest scenarios for the pin and config added.
- Launcher `--mode pcsx2` with `--gs-scale N`; the probe verifies the package tree digest, sets the exe pin and
  writes a minimal `gt4-gs.ini` per session (headless: surfaceless and PNG dumps every 100 vsyncs).
- `tools/gs_live_check`: a producer with a never-shown parent window replays a capture into `gt4-gs.exe` and checks
  attach, resize, snapshot, shutdown and the kill path.

Findings:

- **The TASK-034 480-versus-448 question is the aspect ratio** (Confirmed): PCSX2's default "Auto 4:3" output is
  640x480; 16:9 gives 796x448 and the uncorrected internal size is 640x448. With "Auto 4:3" the v2.8.2 replay of our
  `.gscap` gives PNGs byte-identical to the nightly PoC (frames 60, 300, 700, 1100; 900 within 2 levels).
- Live headless 1x: 41/41 PNGs identical to the offline `--replay-gscap` frames of the same stream, frames 300/700
  identical to the PoC. Donor mode 42/42.
- Costs (menus, headless, unthrottled): game `gs_ipc_write` 0.11-0.21 ms/frame, VSYNC post about 0.01 ms; GS CPU
  thread 0.07-0.10 ms/frame; PCSX2 GS thread 0.6-1.0 ms/frame at 1x and 3x. GPU time is reported as 0 surfaceless
  (Unknown).

Open: owner windowed test at 1x and 3x (image, fullscreen, focus, F7/F8 report), races and 480i, readbacks (TASK-037).

## TASK-039 - GS settings table and `gt4-gs.ini` (main repo)

enforcement stays with the TASK-037/038 agent.

- `scripts/gs_settings.py`: table validation, value checks (refusing unknown ids, unknown choices, out-of-range and

- Tests: `tests/python/test_gs_settings.py` (33 tests): schema, defaults and byte identity, every type and range,
  refusals, INI sections, atomic write (including a failed replace), allow-list stability, offered rows, argument
