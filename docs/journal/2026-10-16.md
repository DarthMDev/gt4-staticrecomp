## Slice204 - TASK-017 halt forensic dump (built, owner run pending)

Branch `task/017-license-crash`, base `6ad39bd` (slice181 license-trace pin fix). Worktree
`C:\Antigravity\gt4-wt-017-license`. No game launched; no card touched.

Why: the analysis of the owner crash (session-20261016-192700, slice181 runtime sha256 deb2c5ef...) found
that thread 17 (the libstream worker, stack 0x008722C0 size 0x1000) is the thread that halted: its saved pc is
0 with the kUnwind bit, and its frames were zeroed. Thread 1 was only preempted inside the record copy loop of
`AutomobileControlRecord::Manager::load` (func_00346CA0, pc range 0x00346BB8..0x00346EB0). Hypothesis: the copy
writes past its 64 KiB record slots and into thread 17's stack. The dump checks that directly, without a
rebuild of `ps2game.lib`.

What changed:

- `scripts/halt_dump_overlay.inc`: overlay on the donor `runtime/src/kernel.cpp` `dump()`. With `GT4_HALT_DUMP`
  nonzero, at the halt it prints `[halt-dump]` lines: per thread the id, status, entry, stack, stack size, pc,
  sp, ra and all 32 saved GPRs (`g_cpu` for the current thread). For a thread whose saved pc is in the copy loop it
  prints `s`, `p`, `i`, `n` (r16..r19), `base` = ld32(s+0x5C), `data` = ld32(s+0x60), the copy source (r3) and
  destination (r6), the 16 words at `p`, and either `overlap thread=<id> ...` or `overlap none` for the window
  `[base, base + n*0x10000)` against every thread stack. Finally it dumps 256 bytes at the halted thread's sp.
  Every guest read is bounds checked against guest RAM (`unreadable`, never a fault). Unset or `0` is silent.
- `scripts/prepare_perf_runtime.py --halt-dump`: derives the overlay from the donor `runtime/src/kernel.cpp`,
  checked against the pinned sha256 `003c9e0a...`. Combined with `--vu0-aot --fsv-trace` it reproduces the
  slice181 `system.cpp`, `vif.cpp`, `vu_micro.cpp` and `cdvdfsv.cpp` byte for byte (checked), plus `kernel.cpp`.
- `native/CMakeLists.txt`: accepts `private/slice204-halt-runtime` in every place slice181 is accepted (perf
  profile, GS async, VU1/VU0 table checks), with `cdvdfsv.cpp` and `kernel.cpp` as capsule sources. Nothing
  weakened.
- Capsule `private/slice204-halt-runtime` (fresh); build `private/slice204-halt-build/build` (Release, clang-cl,
  configured like slice181: worktree source, assets root and generated tables from the main checkout).
- Pins: `docs/inputs/slice204-halt-runtime.json` (derived from the slice181 pin; receipt and source hashes of
  the new capsule, `halt_dump_overlay_sha256` 519027e1...), `docs/inputs/slice204-halt-trace.json`
  (`measurement_mode` `license-halt`; runtime exe sha256 bcf73589f82f069a32ef6322c705382ee6203497b48a4cf3c1443dbe7f1660bd,
  95534080 bytes). slice181 and slice166 pins are untouched.
- Launcher: `external_runtime_probe.py` PERF_PROFILES `license-halt`; the run sets `GT4_HALT_DUMP=1` and
  `GT4_FSV_TRACE=1` for the game and records both in `result.json`. `play_performance.py` docstring updated.
- Tests: `tests/python/test_halt_dump.py` (10 tests): overlay anchors and reversal, donor kernel.cpp pin, capsule

  the real helper text: silent when unset/`0`/empty; `overlap thread=17` for a synthetic record window across the
