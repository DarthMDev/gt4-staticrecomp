## CoreGS 3.0 in scope (owner decision)

- The render pipeline is modernised in stages: CoreGS 2.0 optimises inside VU1 + GS; CoreGS 3.0 (TASK-090) moves the
  VU1 work onto the GPU and renders natively, opt-in, with fidelity as a measured target and effects restored one by
  one. A faithful renderer stays the default; game logic never changes. AGENTS.md scope updated (a native renderer
  was out of scope before); COREGS2-ROADMAP gains the CoreGS 3.0 section and the launcher gate for CoreGS 2.0.

## Roadmap phases (owner decision)

- Phase 1 (Windows PC, 1.x) is done (base of 1.0.0). Phase 2 (current) is CoreGS 2.0, released as GT4Recomp 2.0.0 with
  CoreGS 2.0 as the default renderer and GSdx as the fallback. Phase 3 is native Linux, phase 4 Android, both after
  2.0.0 and both on CoreGS 2.0. The ARMSX2 GS pipeline is no longer the mobile plan (README roadmap, credits row removed;
  AGENTS.md phases updated).

## TASK-091 slice 252: silent self-update, reinstall moves the data

- Self-update: the setup gets `/S /UPDATE /D=<folder of GT4Recomp.exe>` when the launcher runs from the registered
  per-machine install (HKLM `InstallDir`). A portable copy elsewhere, or no registration, starts the setup with no
  arguments. Explorer cannot pass arguments, so its fallback stays interactive (logged). After a silent `/UPDATE`
  run the installer starts the launcher as the player.
- Reinstall into another folder: the installer removes the old program files and records the old data folder as HKLM
  `PreviousDataDir`; the launcher moves its large data at its first start (one marker per source folder, read layer
  until moved, empty old data folder removed).
- The 1.2.0 to 1.2.1 update is unchanged: 1.2.0 passes no arguments, so its setup pages show once.
- Checks: `cargo test --workspace` 343 passed, 0 failed, 4 ignored (was 332). Release launcher sha256
  `0b8d004b2a99273b382c15a79c12554d761d384bbdca5f299f2357cbe5953a83`. Installer
  `private\slice252-installer\GT4Recomp-Setup-1.2.1-test.exe`, 28,845,242 bytes, sha256
  `2FD43DCF6D18FDAE981AF0CD22D79E259E7175ED08DFF41AE3007802A1CF42FF`; 7-Zip extraction matches the launcher. Not
  run on this PC. Owner test: a silent update from 1.2.1, and a reinstall into another folder with the data move.
- Residual risk, not changed: `PreviousDataDir` stays in HKLM after its move. A portable copy started later on the
  same PC would take it as its previous data while that folder still exists (the marker is per folder). Decision for
  the owner: whether the installer should clear the value once the move is done.
