## Seamless install, versions, manual updates, migrations, tray (owner requirements)

Branch `task/019-launcher`, one writer (the agent), no subagents, no game run, no PR, no release.

- **Versions (SemVer).** `version.rs` holds the one `Version` type (strict `MAJOR.MINOR.PATCH`, numeric comparison,
  pre-release tags refused). `releases.rs` holds both streams: GT4Recomp (`moesuito/gt4-staticrecomp`, `vX.Y.Z`,
  `GT4Recomp-Setup-X.Y.Z.exe`) and gt4-gs (`moesuito/gt4recomp-gs`, `gt4gs-vX.Y.Z`, `gt4-gs-X.Y.Z-windows-x64.zip`).
  The old asset name `gt4-gs-<v>-win64.zip` is gone. The renderer minimum is 1.0.1. Drafts and prereleases never count.
- **version.json.** `versions.rs`: schema 1, install folder (fallback: data folder, logged), atomic write, the Cargo
  version is authoritative with a warning, the gt4-gs field is recorded after a renderer install. NSIS writes it at
  install and removes it at uninstall.
- **First run and launch check.** Setup starts the renderer install (`updates::install_renderer`, progress as
  `renderer-progress` events). At every launch `updates::check_on_launch` runs in a thread: version file, the renderer
  if missing, then the update check (6 s timeout). Offers go to the page as `update-available`. Failures are logged.
- **Update popup.** `ui/js/updates.js`: current and new version, what's new (text only; `#`, bullets, `**bold**`),
  Update / Not now / Skip this version. Skip is kept in `settings.toml` under `[updates]`. About has "Check for updates"
  ("You're up to date." when nothing is new).
- **Installs.** gt4-gs: only while the game is not running, into `gs\<version>\`, previous folder kept for rollback.
  GT4Recomp: setup downloaded to `%TEMP%\GT4Recomp-update`, SHA-256 checked, started, launcher exits. The NSIS script
  waits 1.5 s in `.onInit` so the exe is released first.
- **Data is sacred.** `guard.rs` refuses writes under the data folder to saves, cards, library, replays and the runtime
  card folder, and to memory card or save file extensions. Every write in `gs_release.rs`, `versions.rs` and the update
  path goes through it. The NSIS script never touches the data folder; its uninstall checkbox is still unchecked.
- **Migrations.** `migrate.rs` chain framework (first schema, current, steps, plan, backup name). Settings
  (`schema_version`, schema 0 to 1 example), controls (`schema`, a newer file is kept and never overwritten; a damaged
  one gets a copy first), version.json. A backup `<name>.bak-schema<N>-<time>` before any migrated write. The save
  library is a folder with no index file, so it has no chain yet. Documented in `docs/launcher/MIGRATIONS.md`.
- **Tray.** `tray.rs`: pure state machine (game started: hidden; game ended: shown on Home with the message; close while
  the game runs asks first; tray Quit disabled while the game runs). Tauri tray icon with "Show launcher" and "Quit";
  the close button ends the launcher and never goes to the tray.
- **Mock and screenshots.** `dev/mock-data.js` Graphics rows now follow the real GS table (`docs/launcher/gs-settings.toml`):
  Renderer (PCSX2 GS default, CoreGS 1.1 secondary, CoreGS 2.0 greyed), Internal resolution presets 480p to 8K, FXAA,
  CAS and CAS amount, no FSR. Mock events: `?update=1` shows the update popup demo. Screenshots (headless Chrome,
  reduced motion): `docs/launcher/shots/tauri-settings-graphics-1080p-v3.png`, `tauri-settings-graphics-844x390-v3.png`,
  `tauri-settings-about-v3.png`, `tauri-update-popup-v1.png`.
- **Tests.** `cargo test --workspace` green. New: SemVer (3), release lists from fixtures with real renderer asset
  names (4), update decision (7), version.json (7), data-path guard (6), migration chain (11), file-level migrations (6),
  gt4-gs install fixtures (7, names updated to 1.0.x), package verification (1), tray (8), offer view (2). The UI
  contract test lists the new commands.
- **Not done here.** A real NSIS build (the script was edited, not built: `makensis` is not on this machine); a live
  GitHub check and download; the owner's end-to-end test. The gt4-gs 1.0.1 zip layout (`gt4-gs.exe` at the zip root)
