## TASK-100 S7b: unblocked, menus and a race on the Spec II target

- **Root cause of the 2026-10-22 stall [Confirmed].** The Spec II disc reboots the IOP with
  `rom0:UDNL cdrom0:\DNAS310.IMG;1`; the donor runtime enabled its asynchronous FILEIO server (0x80000001, the one
  that answers `devctl` method 23 with the SIF packet `0x80000011`) only when the reboot path contained `IOPRP`. Spec
  II fell back to the synchronous server: the `devctl` on `dev9x` returned -1 and sent no completion packet, and the
  game's fileio thread waited forever on the per-call semaphore (`[sema] 31 count 0 waiters 1` in the dump).
- **The image has nothing to load.** DNAS310.IMG (282,545 bytes) is the same romdir as IOPRP300.IMG (278,465 bytes):
  RESET/ROMDIR/EXTINFO and the same 16 Sony system modules (SYSMEM … STDIO) in the same order, no two byte-identical.
  The runtime already serves those modules as native HLE for both games, so the fix is the FILEIO protocol, not a
  loader. Pin `docs/inputs/spec2-dnas310.json`; tool `scripts/spec2_iop_image.py`; section in docs/IOP-MAP.md.
- **Fix.** New runtime capsule `private/slice276-spec2-iop-runtime` (slice262 profile + `--spec2-iop`):
  `scripts/spec2_iop_overlay.inc` derives `sif.cpp` so a DNAS310.IMG (or IOPRP*) reboot selects the asynchronous
  FILEIO server and logs the LOADFILE version read from the image (`native/spec2_iop.hpp`). CMake gained
  `GT4_FRAME_CAPSULE_RE` (slice260-279), the `sif.cpp` slot for a slice27x capsule, and a v2.00-pinned copy of the
  three hook modules for the v2.00 hook fixtures (`GT4_TARGET_FIXTURE_V200`, `gt4_quickfix_v200_fixture`), so the
  v2.00 checks still run in a Spec II build.
- **Headless evidence** (`O:\gt4recomp-scratch\spec2-s7d-build`, derived ELF `36f60b1a…`, donor renderer 1x):
  - 4,200 menu frames: all requested IRX modules load (DEV9 … RTINETB, PPP/PPPOE included), 1,805,640 primitives;
  - frames reviewed by eye: language menu, game-data dialog, "Welcome to Gran Turismo 4 Spec II" name entry, the
    intro movie, the main menu (Arcade Mode highlighted), Arcade Mode Selection, Single Race circuit categories,
    City Courses, car selection (Ford RS200 '84), and a running race at Costa di Amalfi with HUD, position, lap timer
    and minimap (21,000 frames, 169,687,609 primitives);
  - no "no translated code" in any run.
- **Checks.** CTest 43/43 in the Spec II build (new `native_spec2_iop`). Python suite: 668 tests, all pass with the
  Spec II build (51 skipped); with the v2.00 build only the expected release-pin distribution failure. v2.00 identity
  re-run against `private/slice268-build` with `GT4_GS_STREAM_HASH=1`: menus `463d455c…`/`1ccb97c5…`, day
  `992f1ac9…`/`0c79dcf5…`, night `c57e7d03…`/`c091716e…` — all six equal.

## TASK-100 S8b: license demo guard for Spec II

- Problem: every `license_*` field of `kSpec2Hooks` was 0, so the TASK-017 guard (the crash mitigation for license
  demos that our FPU decrypts in the wrong key-stream phase) was off on the Spec II target.
- Values, all located from the v2.00 code shapes in the derived Spec II ELF and then checked against the demo files:
  `RaceSolitaire::loadDemoInputs` `0x2012C8` (RaceSolitaire vtable base `0x6B3130` at `+0x510`; the v2.00 base
  `0x680140` has the same virtual at `+0x4D8` -> `0x3EAD18`), loaders `0x10CA18`/`0x10CBA8` with return labels
  `0x10CB54`/`0x10CCE4` (each calls the `license/%s` helper `0x1A8BE8` and makes exactly one `jalr`: vtable `+0x510`
  and `+0x1C8`), `AutomobileControlRecord::Manager::load` `0x207AA0`, game CRC-32 table `0x731DB0` (all 256 words
  equal the standard reflected table), Manager add `0x1A24` and loader body pointer shift `0x80` (High confidence).
- Cipher and format: `0x459E90` (v2.00 `0x579E00`) via `0x2E3CE8`, FT at `0x667048` (matches the derived formula on
  all 256 entries) and T8 bytes at `0x731C98` (bit reversal) - the same cipher. The Spec II volume catalogues 26,891
  files and 256 `replay/license/*` demos (RoFS 3.1 TOC at `0x115B800`; its leaf pages carry an odd count, so the
  pinned reader's parity check was relaxed in scratch only); 171 names are shared with v2.00 and 170 bodies are
  byte-identical. The beta disc keeps the same 256 plus 381 in `replay/license.old`, also retail format.
- The demo body layout is unchanged: a CRC-confirmed beam search on `cnl0a0001`/`cnl0b0001` returns the hardware
  plaintext (`u32 body size`, `GT4M`, `RaceLicense`) with the single-Recorder Manager stream at body `+0x1AA4`, the
  Recorder size ending exactly at the body end. The code's `0x1A24` add therefore applies to a pointer the loader
  hands the virtual `0x80` into the body (`0x1A24 + 0x80 = 0x1AA4`). The pointer itself was not observed at runtime
  (GT mode needs game data; the seed cards have none), so that one link is High confidence and the owner license run
  is the remaining gate.
- Guard change: `HookAddresses` gained `license_manager_add` and `license_body_shift`; `license_guard.hpp` keeps the
  layout constant `kManagerOffset = 0x1AA4`, adds `manager_address(a1) = a1 + add`, and a static assert that
  `add + shift == kManagerOffset` on qualified targets. The overlay evaluates the CRC and the layout at the header's
  own body start (`buffer + offset`) and writes `n = 0xFFFFFFFF` at the Manager address the virtual itself reads
  (for Spec II `a1 + 0x1A24`). The overlay text changed, so it was re-derived into the fresh capsule
  `private/slice277-license-guard-runtime` (slice262 profile: aspect + frame counters), pinned in
  `docs/inputs/slice277-license-guard-runtime.json`; CMake accepts slice27x guard capsules and the Spec II build uses
  it, while v2.00 keeps the pinned slice262 capsule.
- Oracle on the 256 Spec II demos with our FPU (`chop/chop`): 0 pass the game CRC, 114 still decrypt to the
  single-Recorder layout, so the guard writes for 142 demos. `chop/nearest` 123 sane/133 guarded, `chop/srt2-cs-t1`
  104/152, `chop/srt2-cs-t3` 115/141, `chop/srt2-la-t3` 126/130.
- Tests: CTest 44/44 in the Spec II build (`native_license_guard` keeps the v2.00 rule; `native_game_target` and the
  extended `native_spec2_hooks` assert the Spec II values, that only `0x10CB54`/`0x10CCE4` key the guard, the

## TASK-100 S8c: the Options-menu halt and the entry-seed sweep

- Root cause (Confirmed): the call at `0x0050D1A8` is `jalr $v1` with `v1 = lw 16(s1)` (a callback in the Options
  descriptor). The Options page builds the pointer itself: `lui s0,0x003D` at `0x003CC8EC`, `addiu s0,s0,-22896` at

  instructions, there is no literal dataword for `0x003CA690`, and the call graph cannot see the object field, so the
  address never became an entry.

  and writes the translator's `--entries` delta: wide `luipair` (window 64, clobber-aware), stack-frame fallthrough
