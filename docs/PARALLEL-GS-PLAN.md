## 1. paraLLEl-GS interface (as read in `gs/gs_interface.hpp/.cpp`, `gs_renderer.cpp`)

- `init(Vulkan::Device*, GSOptions)`: GSOptions {super_sampling X1..X16, vram 4 MiB,
  dynamic_super_sampling, ordered grid, super_sampled_textures}. Feature check in
  `GSRenderer::init` (returns false with a list). Starts a `PGS-Waiter` thread and
  `std::async` pipeline-precompile threads.
- `gif_transfer(path, data, bytes)`: own GIF parser per path (PACKED/REGLIST/IMAGE, PRE→PRIM,
  internal Q reset, optimized handlers for common packet shapes). Path state persists across
  calls (`get_gif_path`). IMAGE → HWREG accumulation; upload kicked when RRW*RRH*bpp is reached.
- `write_register(addr, value)`: A+D semantics. TRXDIR: LOCAL→LOCAL GPU copy; HOST→LOCAL
  awaits HWREG; **LOCAL→HOST: flushes and waits only on the timeline value of the pages it
  reads, then decodes into a FIFO buffer**; `read_transfer_fifo(dst, n)` drains it (zeros past end).
  `Hacks::unsynced_readbacks` returns zeros instead of waiting (diagnostic only).
- `map_vram_write/end_vram_write/map_vram_read`: page-tracked host access (state load/save, dumps).
- `flush()`: submits pending work (non-blocking). `vsync(VSyncInfo)` → `ScanoutResult`
  {Granite ImageHandle in `dst_layout`, internal/mode size, interlaced, high_res}; options:
  phase, force_progressive, overscan, anti_blur, crtc_offsets, adapt_to_internal_horizontal_resolution,
  raw_circuit_scanout, high_resolution_scanout (≥4x SSAA), skip_deinterlace. Reads PMODE/SMODE1/
  SMODE2/DISPFB/DISPLAY/BGCOLOR from `PrivRegisterState`; CSR/IMR are stored only (no IRQ logic).
- `SignalInterface::on_signal/on_finish/on_label(payload)`: called inline on the caller's thread;
  returning true forces a flush. IRQ/CSR/SIGLBLID semantics are the host's job.
- `set_super_sampling_rate` (runtime), `set_hacks` (disable_mipmaps, unsynced_readbacks,
  backbuffer_promotion, allow_blend_demote), `set_debug_mode` (timestamps,
  deterministic_timeline_query), `consume_flush_stats`, `get_accumulated_timestamps`.
- Threading: GSInterface is single-caller (not thread-safe); internal worker threads only.
- Device/presentation: needs a Granite `Vulkan::Device` (its own allocator, command buffers,
  timeline semaphores, frame contexts — `Device::next_frame_context()` must be called every
  frame or deferred deletions accumulate). paraLLEl-GS never presents; the host draws/blits
  `ScanoutResult.image`. Granite `WSI` + a `WSIPlatform` subclass provides swapchain/present;
  `CommandBuffer::swapchain_touch_in_stages()` is the documented hook for transfer-only use.

**Boundary decision: (a)** — at the GIF-transfer boundary, not register forwarding. Reasons
[C from source]: the donor's `write_packed` updates `s.st`, `s.q`, `s.rgbaq`, `s.uv`, `s.fog`
without calling `write()`, so forwarding `gs::write` would miss packed state; paraLLEl-GS's
own GIF parser has optimized packed handlers and path state; double parsing wastes CPU.
Keep donor GIF/VIF/DMA/IRQ/privileged-register model as the front end; keep the donor
renderer in the same binary as fallback, chosen once at `gs::init()`.

**Vulkan device decision: Granite owns instance, device and swapchain** in parallel mode;
our `native_vulkan` Context is not created at all (renderers are mutually exclusive per run).
Justification: paraLLEl-GS needs a Granite `Device` with Granite's feature chain (descriptor
heap/buffer flags, BDA, subgroup size control, 8/16-bit storage), Granite allocator, timeline
and frame-context lifetime. Sharing our VkDevice via `DeviceFactory` would force `native_vulkan`
to adopt Granite's feature chain and queue locking anyway, and couples two renderers that never
run together. Presentation: Granite `WSI` with a ~80-line `Win32Platform : WSIPlatform`
(vkCreateWin32SurfaceKHR on the existing HWND, client-rect size), `PresentMode::SyncToVBlank`
(FIFO), UNORM backbuffer (PS2 output is already display-referred; sRGB would double-encode),
`set_extra_usage_flags(TRANSFER_DST)`, clear + `blit_image` with the aspect rect from
`gt4::vulkan::presentation_rect`, `swapchain_touch_in_stages(BLIT)`, barrier to PRESENT_SRC.
`window.cpp` pacing (`release_frame` grid, FIFO, audio pump) is unchanged; it still calls
`ps2::gs::present()` once per VBlank. `GRANITE_VULKAN_DXGI_INTEROP=OFF` initially (overlay/
pacing behaviour comparable to today); evaluate ON later. Async ring (slice 152) is not used:
paraLLEl-GS already submits without waiting and waits per page only.

  pipelines (GPU shader compilation is allowed). Do not enable Granite's runtime GLSL compiler.
- Licenses: add a `native/THIRD_PARTY.md` section: paraLLEl-GS LGPL-3.0-or-later (COPYING.LGPLv3,
  SPDX headers, Arntzen Software AS), Granite MIT (Hans-Kristian Arntzen), volk MIT (Arseny
  Kapoulkine), Vulkan-Headers Apache-2.0 OR MIT. Static linking of LGPL code: distribution must
  allow relinking (provide object files or full corresponding source + build scripts); compatible
  with the project's GPL direction. External contributions not accepted upstream: local patches
  stay in our tree as documented patch files, never pushed upstream.

## 6. Risks and fallbacks

- Not bit-exact interpolation → tolerance-based gates; owner visual judgement is final.
- GT4 channel-shuffle brightness/fade: paraLLEl-GS detects channel shuffles generically [C],
  no GT4-specific path [C]; verify early with captured streams; fallback: report upstream-style
  repro via dump, keep donor.
- Half-pixel/HUD: no `halfPixelOffset` hack exists in paraLLEl-GS (it rasterizes like the GS);
  check at 1x first, SSAA later.
- SetGsCrt synthesis wrong → black screen ("Unknown video format"): logged, never silent.
- Two Vulkan header versions in one binary → isolate TUs; ODR on `vk*` prototypes avoided by volk.
- Startup pipeline stalls (~2 s observed) → accept initially; persistent pipeline cache later.
- Thread affinity: all GSInterface calls from the emulation thread (same as today); a future
  GS thread (TASK-0xx) would move the whole backend.
- LGPL obligations for distribution; owner decision recorded before any public binary.
