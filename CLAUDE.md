**Read `AGENTS.md` first.** It holds the binding project rules: mission (no JIT,
phase 1/phase 2), owner communication (Brazilian Portuguese, plain language; repo

`docs/STATUS.md`; the active plan and backlog are in `docs/OPTIMIZATION-PLAN.md`;
daily progress goes to `docs/journal/YYYY-MM-DD.md`.

## What this is

A static recompilation of Gran Turismo 4 (NTSC-U SCUS-97328) to Windows x86-64 +
Vulkan, built on the MIT ps2-web-recomp donor. Game data, the ELF, the translated
EE library and all build outputs are private and git-ignored under `private/`; a
clean checkout cannot build the game.

## Commands

All native work runs from the repo root through a VS x64 environment (`cmd /c`
with `VsDevCmd.bat -arch=amd64 -host_arch=amd64`; see `native/build.cmd`). Run
builds and tests serially.

- Configure a candidate build (current recipe = slice 153; each new candidate
  uses fresh `private/sliceNNN-*` dirs and new `docs/inputs/*.json` pins):
  ```
  cmake -S . -B private\slice153-pacing-build\build -G Ninja -DCMAKE_BUILD_TYPE=Release ^
    -DCMAKE_CXX_COMPILER="C:/Program Files/LLVM/bin/clang-cl.exe" ^
    -DGT4_EE_PROFILE=production -DGT4_ASSETS_ROOT=C:/Antigravity/gt4-staticrecomp ^
    -DGT4_PYTHON=private/tooling-venv/Scripts/python.exe ^
    -DGT4_PERF_RUNTIME_SOURCE=private/slice151-vu1-aot-runtime ^
    -DGT4_VU1_GENERATED_DIR=private/slice151-vu1-gen-smoke ^
    -DGT4_PORT_DIR=private/slice153-pacing-port -DGT4_SHADER_DIR=private/slice153-pacing-shaders
  ```
  CMake refuses port/shader/runtime combinations that do not match the pins.
- Rebuild an existing dir: `cmake --build private\slice153-pacing-build\build`
- Baseline (slice 114) build: `cmd /c native\build.cmd`
- Tests: `ctest --test-dir <build dir> --output-on-failure`; one test:
  `ctest --test-dir <build dir> -R native_pacing --output-on-failure`
- Python suite (must point at the build under test, otherwise it checks the
  stale slice 114 binaries and two tests fail):
  `GT4_NATIVE_BUILD=<build dir> private/tooling-venv/Scripts/python.exe -m unittest discover -s tests/python`
  One test: `... -m unittest tests.python.test_pacing_launcher` (run from repo root with `-s`/`-t` as needed).
- Launch for owner testing: `private\tooling-venv\Scripts\python.exe scripts\play_performance.py --assets-root C:\Antigravity\gt4-staticrecomp --mode pacing`
  (modes map to pinned manifests: `vu1-aot`, `gs-async`, `pacing`, `vu1-record`;
  options `--vu1-verify N`, `--vu1-interpret-only`; env `GT4_PACING=audio`,
  `GT4_GS_SYNC=1`, `GT4_PRESENT_MODE`). F7 starts a measured interval, F8 writes
  the report to `private/manual-play/session-*/probe.log`.
- VU1 emitter: `gt4_vu_recomp <corpus dir> <fresh out dir>` (built from `tools/vu_recomp`; refuses non-empty output dirs).

## Architecture (big picture)

- **EE pipeline:** ISO → `CORE.GT4` → reconstructed ELF (`private/reconstructed/SCUS_973.28.elf`)
  → donor translator (`tools/ee_producer`, `scripts/ee_producer.py`) → 326 C++ units
  (`unit_XXXX.cpp`, one per 16 KiB address window, `switch(entry)` to labels) →
  pinned `ps2game.lib`. A call to an address without a translated entry halts
  ("no translated code"); there is no EE interpreter.
- **Donor runtime** (`private/references/ps2-web-recomp/runtime`) is frozen and
  hash-checked. Behavior changes go through overlay capsules generated by
  `scripts/prepare_perf_runtime.py` (e.g. `--vu1-aot` applies
  `scripts/vu1_aot_overlay.inc` to `vu_micro.cpp`) and selected by `GT4_PERF_RUNTIME_SOURCE`.
- **Native adapter** (`native/`): the donor GS backend `gpu.cpp` is spliced with
  `native/gpu_*.inc` by `scripts/prepare_external_vulkan.py` into a port dir;
  `native_vulkan.cpp` (Vulkan context, 3-slot async submit ring, present),
  `window.cpp` (Win32, VBlank hook, F-keys), `host_io.cpp` (WinMM audio, XInput,
  keyboard), `pacing.cpp`/`frame_clock.cpp` (single-clock frame pacing, audio rate
  control), `perf_probe.*`/`perf_accounting.hpp` (F7/F8 timing categories).
  Shaders are the donor WGSL compiled to SPIR-V by `tools/wgsl_spirv` (naga).
- **VU1 AOT:** the whole VU1 microcode image is XOR-encrypted in the ELF (file
  offset 0x525DD0, see `docs/VU1-MICROCODE-SOURCE.md`); `tools/vu_recomp` emits C++
  per (key, entry) with identity digests, budget/resume contract
  (`vu_recomp_contract.hpp`) and differential tests against the donor interpreter.
  Unseen entries fall back to the interpreter and are counted in F8.
- **Launchers and pins:** `scripts/play_performance.py` → `scripts/play_external_runtime.py`
  → `scripts/external_runtime_probe.py`, which verifies every file against
  `docs/inputs/*.json`, scrubs inherited `PS2_*`/`GT4_*` variables, backs up and
  locks the owner's memory card, and records the run in `result.json`.
- **References used for research** (private clones): gt4-decomp (names/types at
  identical addresses: `private/slice151-research/gt4-decomp`), Nenkai repos,
  PCSX2 (`private/tooling/pcsx2-slice101-source`).

## Gotchas

- Never overwrite an existing `private/slice*` directory or edit an existing
  manifest to make a hash match; create a new slice.
- After a rebuild the executable hash changes; the launcher manifest pin must be
  regenerated (Python pin tests enforce it).
- This machine's AMD driver reports `maxComputeWorkGroupCount[0] = UINT32_MAX`;
  fixtures must derive limits from the device.
- The owner's card at `private/manual-play/card.ps2` and its lock/backups must be
  preserved; do not launch while an owner session is running.
